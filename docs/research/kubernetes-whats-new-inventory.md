Inventory date: October 5, 2026. Kubernetes scope: v1.35, v1.36, and v1.37 only. CNCF promotion scope: calendar years 2025 and 2026 through this date.

## Source and evidence boundary

The candidate source is Bret’s [k8s-catch-up skill](https://github.com/BretFisher/skills/blob/main/skills/k8s-catch-up/SKILL.md), updated September 30, 2026. The local entrypoint and all 96 feature reference files were read in full. `references/how-to-update.md` is a maintenance guide, not a candidate feature, and is excluded.

The skill claims release dates of December 17, 2025 (v1.35), April 22, 2026 (v1.36), and August 26, 2026 (v1.37). These are source claims. This inventory does not independently verify releases, maturity, defaults, fields, or migration deadlines. The chapter must use the linked verification notes when they disagree with the skill.

## Corrections to apply when teaching

- cgroup v1: the skill filename says “removal,” but its body describes default kubelet refusal from v1.35 with a temporary override. Do not describe this as removal of all support.
- SELinux labeling: the skill separates two gates that became stable in v1.36 from `SELinuxMount`, which it claims became stable in v1.37. Do not assign the entire change one graduation version. Use the security evidence note for the verified split.
- Identity APIs: a stable delivery API does not install a certificate signer or make user namespaces the default for every Pod. Node, driver, signer, and feature configuration still control availability.
- Default conflicts: storage version migration and HPA tolerance contain conflicting defaults in the skill. Use component source and official gate history from the evidence notes.
- Future dates in removal references are plans, not completed removal events. The candidate tables retain skill claims so these differences stay visible.

## Why these themes were selected

- **Workload and node security:** explicit groups, user namespaces, private-image checks, CSI token handling, and SELinux mount labels address practical access boundaries.
- **Identity and policy:** in-process mutation, external signing, narrow kubelet permissions, constrained impersonation, Pod certificates, and trust bundles change platform architecture.
- **Resource behavior:** container resize, observed generation, restart rules, terminating replica counts, HPA settings, and Memory QoS improve workload operation and upgrade planning.
- **Storage and networking:** image volumes, changing attach limits, unused PVC status, local traffic preferences, and strict address validation affect common cluster workloads.
- **Accelerators and batch placement:** DRA resource-name requests, device taints, gang scheduling, and the PodGroup API explain important changes without teaching every driver field.
- **Upgrade actions:** all seven removal/deprecation references remain in scope so operators can identify migration work.
